# 无人机照片工具（uav-photo-tool）

一个**免安装**的 Windows 小工具，用来预处理无人机航测照片。装上或者直接解压就能用，不需要装 Python 和任何库。

最初是为**室内航测**写的：室内 GPS 信号差，同一架次里有的照片坐标是 0,0，有的在漂，有的又是 RTK 固定解。空三软件把这些坐标当作先验，结果互相打架，对齐不上。这个工具先把定位信息剥掉，再做只靠影像匹配的空三。

> English: A zero-dependency Windows tool for preprocessing drone survey photos. It strips GPS/location metadata from DJI JPEGs **byte-for-byte without re-encoding the image**, and can drive Agisoft Metashape Pro to align the photos and export a Blocks Exchange XML that ContextCapture / iTwin Capture Modeler can import. For repeated surveys of the same site it can also transfer ground control points from a reference epoch with zero manual tie-pointing, adjust, self-check, and export the block in local metric coordinates.

## 功能

### 1. 剔除定位

把一个目录（可含子目录）里的 JPG 照片去掉定位信息，默认另存到新目录，**原片不动**。也可明确选择「原地抹除」直接改原照片；该模式默认先写定位备份，之后可逐字节还原。定位一旦从照片中抹掉，不能仅靠照片本身找回，只能依靠备份。

- 删除的内容：
  - EXIF 里的 GPS 信息；
  - 大疆 XMP 里的位置字段（`GpsLatitude`、`GpsLongitude`、`AbsoluteAltitude`、`RelativeAltitude`、`GpsStatus`、`Rtk*`、`LRFTarget*` 等）。
- 可选：同时剔除姿态，也就是云台和机身角度（`Gimbal*`、`Flight*`）。
- 保留的内容：相机标定参数（`DewarpData`、`Calibrated*`）、拍摄时间、相机型号、缩略图。
- **只改元数据，不重新压缩图像**：
  - 输出文件和原文件大小相同；
  - 图像数据逐字节不变；
  - 文件名和修改时间也保持不变。
- 默认输出到同级目录 `<原目录名>_去定位`。输出目录不是空的就拒绝写入，避免覆盖。
- 非 JPG 文件（如 `.MRK`、`Thumbs.db`）会跳过，并记进日志 CSV。

**原地抹除（谨慎使用）**：命令行用 `strip-gps <照片目录> --in-place --confirm <目录名>`，确认名必须是目录名而不是完整路径；默认在第一张照片改动前写入并校验 `定位备份_<时间>.zip`，`--no-backup` 可关闭。每张照片先写同目录临时文件并自检，通过后才原子替换。用 `restore-gps <照片目录> --backup <定位备份.zip>` 还原；只有当前文件哈希仍等于抹除后的哈希才会写回，其他修改过的文件跳过。界面勾选「原地抹除」后会要求输入目录名确认。

### 2. 空三（需要 Metashape Pro）

调用你电脑上已安装的 **Agisoft Metashape Pro** 对齐照片，导出 **Blocks Exchange XML**。

- 第一次使用时选择 `metashape.exe` 的位置（老版本是 `photoscan.exe`），之后会记住。
- 照片还带定位时，默认先自动去定位再空三。Metashape 里也会关掉位置和姿态参考。
- 默认参数：高精度、关键点 40000、连接点 4000。精度和两个上限可以在界面上改。
- 结果输出到 `<照片目录名>_空三\`，包括：
  - Metashape 工程（`.psx`）；
  - Blocks Exchange XML；
  - 空三报告：写明对齐了几张、没对齐的是哪几张；
  - Metashape 日志。
- **导出的 XML 不带坐标系**（局部坐标，尺度任意），可以直接导入 ContextCapture。之后在 CC 里加控制点再做一次空三，就能得到真实坐标。
- 只对齐了一部分照片时，XML 只写已对齐的相机，工程文件里保留全部照片。
- 可以批量处理：每个含照片的子目录单独做一个工程。

### 3. 控制点（需要 Metashape Pro）

给空三结果加上控制点、平差到真实坐标（局部坐标，单位米），导出 ContextCapture 能直接用的 Blocks Exchange XML。适合**同一场地反复航测**（比如每期框架、控制点都不动）：第一次刺一次点，以后每期都不用刺。

有两种模式：

- **建参考期**（新场地第一次用）：
  - 输入：「空三」页签产出的 `.psx` + 控制点 CSV。
  - 刺点来源二选一：ContextCapture 导出的 Blocks Exchange（`.xml` 或 `.xmlz`，里面有你在 CC 里刺的点）；或者先在 Metashape 里给至少 3 个点、每点至少 2 张照片刺好并保存。
  - 软件把其余照片上的点自动补上、细化、平差，输出的 `.psx` 以后当「参考期」用。
- **迁移**（以后每一期，零刺点）：
  - 输入：新一期照片目录 + 参考期 `.psx`。
  - 软件把新照片和参考期一起匹配，按参考期的控制点自动放点、细化、平差。参考期的照片要留在原来的位置。
  - 一次约 5 分钟，其中联合匹配占 3～5 分钟。
- 两种模式都输出到 `<名字>_控制点\`：`.psx`、Blocks Exchange XML、`控制点报告.txt`、Metashape 日志。原工程只读，不会被改。

**控制点 CSV 格式**：每行 `点名,X,Y,Z`，单位米。

- 可以有表头；表头里写了 X/Y/Z，就按表头取列。
- 分隔符可以是逗号、制表符、分号或空格；编码 UTF-8 或 GBK 都行。
- 全站仪常用「X 北、Y 东」，和软件要的 X/Y 正好相反。建参考期时软件会把原样、X/Y 对调各算一次，相差 10 倍以上就自动判定，并在报告里写明（如「CSV 的 X/Y 对调了，已按对调后的坐标用」）。差别不到 10 倍时只提示你自己核对 CSV。
- CC 刺点的像素坐标比 Metashape 的小 0.5 像素（两边像素原点的约定不同），软件读 CC 刺点时已经自动加上了。

**怎么判定**（每个控制点）：

- 三维误差 ≤ 2×控制点精度（默认精度 0.01 m，也就是 20 mm）；
- 像素 RMS ≤ 3；
- 至少 3 张照片。

全部通过就是「自动通过」，否则是「需人工核对」，报告里会列出是哪些点、为什么，并附处理步骤。另外：

- 像素残差特别大的投影会先自动删掉，再重新平差。
- 迁移时，「细化标记点」把某个点挪动超过 50 像素，多半是认错了角点（比如降雨前后场景变了）：
  - 只是个别投影挪得远：把这几处投影删掉；
  - 这个点挪动的中位数超过 50 像素：整点自动排除，不参与平差，改作检查点（误差照报，仅供参考）。
  - 只要有点被自动排除，结论就是「需人工核对」。
  - 上限可以改：界面「细化挪动上限」，命令行 `--max-shift`。
- 报告里的「迁移偏差（细化挪动）」一栏，是自动放的位置和按图像细化后的位置相差多少像素，越小说明迁移越准。
- 你也可以手动排除某些点（界面「排除的控制点」填 `1,2`，命令行 `--exclude 1,2`）。被排除的点同样当检查点，不影响「自动通过」。
  - 已知问题：「迁移」模式里点名写错（比如参考期里没有 9 号却填了 `9`）时，要等 Metashape 启动后才报错，结论是「失败」（退出码 1），并留下一个不完整的输出目录。删掉这个目录、改对点名重跑即可。「建参考期」模式会在开跑前直接拒绝（退出码 2）。以后会统一成开跑前拒绝。
- 参与平差的点少于 3 个，判「失败」。

**导出的 XML** 写的是 ContextCapture 自己的局部米制坐标系（`Local:unit=meter`），区块和每个控制点都挂了坐标系，所以导入 CC 后单位显示为「米」。被排除的点在 XML 里标成检查点，CC 平差时不会用它们。「空三」页签的输出不受影响，仍然不带坐标系。

**批量迁移**（「批量迁移」页签，命令行 `gcp-batch`）：把一个上级目录下的每一期照片挨个做「迁移」，最后出一张汇总表。

1. 选「照片上级目录」（每个**直接**含 JPG 的子目录算一期；名字以 `_去定位`、`_空三`、`_控制点` 结尾的不算）、「输出目录」和 Metashape。
2. 填参考期规则表：每行是「关键词 + 参考期 .psx + 排除点（可空）」，默认两行「梯田」「植被」，可以增删。一期按名字从上到下匹配第一条规则；都不匹配就跳过。规则表会记住。
3. 选「照片处理方式」（见下面）；「跳过这些期次（逗号分隔）」里填不想跑的期次名（比如参考期本身），会记住。
4. 点「扫描」：列表每行一期，列出序号、期次、匹配规则、照片数、参考期、状态（待运行 / 待运行（上次已取消）/ 待运行（上次失败）/ 已有结果 / 跳过：原因）。默认勾上所有「待运行…」的期；跳过名单里的期显示「跳过：在跳过名单里」、不勾。
   - 筛选框输入「梯田」等文字可以过滤，**只影响显示，不会清掉已勾的**；「全选」「全不选」「反选」「只勾待运行」只作用于当前显示的行。
   - 规则表里参考期路径太长时显示尾部（文件名），鼠标停在上面会提示完整路径。
5. 点「开始」：勾上且「待运行…」的期一期接一期地跑（不并行），进度条旁显示「第 i/N 期」。每期开跑前如果本机已有别的 Metashape 在跑，就先等它结束（显示「等待其他 Metashape」）。每期结束后，列表里的状态变成结论和 RMS3D；全部跑完的弹窗列出需人工核对、失败的期次名。
   - 已有结果（报告判定为「自动通过」或「需人工核对」）的期跳过；已有 `<名>_去定位` 照片就直接用，不再去定位（中途停了重跑会接着做）。
   - 「取消」只停当前这一期，剩下的不再开始；已完成的期次结果都保留。被取消或失败的那一期，重新扫描会显示「待运行（上次已取消）」或「待运行（上次失败）」，勾上再跑就行：开跑前软件把旧的结果目录改名为 `<原名>_上次已取消_<时间>`（或 `_上次失败_<时间>`）**保留，不删除**，不要的话自己删。
   - 跑批时点窗口的关闭按钮会先问一下；确认后停在当前这一期（当前这一期算取消），停好后窗口自动关闭。
   - **判定会有波动**：同一期同一参考期跑两次，可能一次「自动通过」、一次「需人工核对」（像素 RMS 压在 3 附近的点）。判了需人工核对的期可以先重跑一次：把输出目录里它的 `_控制点` 目录改名或删掉，再扫描、勾上、开始。
6. 汇总表 `<输出目录>\批量迁移汇总_<时间>.csv`（UTF-8 带 BOM，Excel 可直接打开），每跑完一期写一次，列：序号、期次、类型、照片数、参考期、排除点、状态、退出码、判定、RMS3D、对齐、耗时分钟、报告、照片处理（复制 / 原地抹除 / 用已有去定位 / 原片无定位）、定位备份（本次写的备份 zip，没有就空）。完整日志在 `批量迁移日志_<时间>.txt` 和各期的 `<名>_运行日志.txt`。

**照片处理方式**（两种二选一，每次启动都回到第一种）：

| | 复制一份去定位照片到输出目录（默认） | 直接在原照片上抹除定位 |
|---|---|---|
| 原照片 | 不动 | **会被修改**：只改定位相关的元数据，图像数据逐字节不变、文件名和修改时间不变 |
| 空间 | 每期在输出目录多一份 `<名>_去定位` 照片，按原照片大小估算（七十来期约几百 GB） | 不复制；每期照片目录里多一个定位备份 zip（只存元数据，很小）和一份抹除日志 |
| 结果目录 | `<名>_去定位_控制点` | `<名>_控制点` |
| 命令行 | 默认 | `--in-place --confirm <照片上级目录的名字>` |

原地方式：
- 点「开始」后弹一个红色确认框，写明要改多少期、多少张照片，必须输入**照片上级目录的名字**（不是完整路径）才开始；输错或取消什么都不做。命令行 `--confirm` 不对，退出码 2，什么都不动。
- 照片上级目录或某一期的照片目录不可写（只读盘、没有写权限），整批拒绝、什么都不动、不建输出目录。
- 每期：输出目录里已有 `<名>_去定位` 照片就照旧用它，不碰原片；否则原片里有带定位的照片就先抹除（先写并校验备份 `定位备份_<时间>.zip`，在这一期的照片目录里），**有一张没抹成这一期就判失败、不做迁移**；照片本来都没定位就跳过抹除。
- **还原**：「剔除定位」页签选这一期的照片目录，点「从备份还原」选那个 zip；或命令行 `uav_photo_tool.exe restore-gps <这一期的照片目录> --backup <定位备份_时间.zip>`。还原后与抹除前逐字节相同。
- **原地方式中途取消再重跑，同一期会多一份备份**（第一份是取消前已抹的照片，第二份是重跑时剩下的照片），**两份都要留**；还原时两份都用一遍（顺序不限，已还原或没抹过的照片会自动跳过）。

命令行（先加 `--plan` 看一遍序号和每期会用哪个参考期）：

```powershell
uav_photo_tool.exe gcp-batch <照片上级目录> --out <输出目录> `
    --rule 梯田=<梯田参考期.psx>[:排除点] --rule 植被=<植被参考期.psx> `
    [--include "*梯田*"] [--pick 1,3,5-9] [--skip 名字1,名字2] [--in-place --confirm <上级目录名>] `
    [--plan] [--metashape 路径] [--log 日志文件]
```

- `--rule` 可以给多次，按给的顺序匹配；例如 `--rule 梯田=D:\参考期\梯田.psx:4` 表示梯田各期都排除 4 号点。
- `--include` 按名字通配符筛（多个用逗号隔开），`--pick` 按扫描序号选，两个一起用时取交集；`--skip` 是跳过名单，列出的期次标为「跳过：在跳过名单里」（比如参考期本身）。
- 一台电脑跑梯田、另一台跑植被：各自只给一条 `--rule`，或用 `--include`。
- 默认每期都会在输出目录里存一份去定位后的照片，空间按原照片大小估算；加 `--in-place --confirm <上级目录名>` 改为直接在原照片上抹除定位（见上面「照片处理方式」）。

旧的 PowerShell 脚本 `scripts/batch_gcp_transfer.ps1` 已由这个页签取代，只作参考。

### 4. 影像处理（需要 Metashape Pro）

给室外实景航测用（如铁路弃渣场月度巡查）：扫描一个月的照片目录，勾选要做的工点，一个接一个让 Metashape 做完空三，导出 **ContextCapture 能直接导入、不用再空三**的 Blocks Exchange XML，坐标系是 **CGCS2000 3 度带（东坐标不带带号）**；可选直接出 DOM、DSM。

> **精度说明**：本页签**不去定位**（和其他页签相反）——室外照片的 GPS 是有用的，直接拿来当相机位置参考。照片只有机载普通 GPS（没有 RTK）、也没用控制点，所以坐标是**米级**精度（实测相机参考误差 RMS 约 1～3 米，高程误差比平面大），高程用照片记录的高度，没有做高程基准改正。要厘米级请在 CC 里加控制点再空三。

1. 选「照片上级目录」（只读，软件不会往里写任何东西）、「输出目录」（不能放在照片目录里面）和 Metashape。
2. 点「扫描」：
   - **工点**：每个**自己直接含 JPG**、且不在另一个工点里面的文件夹算一个工点；它下面子文件夹（如 `正摄\`）里的照片都并进来，**所有照片都用**（斜拍的也用）。自己不直接含 JPG 的文件夹往下找（所以 `无正射影像\<子文件夹>` 各算一个工点）。只有 `正摄\` 一个子文件夹的工点，工点名取外面那一层的名字。
   - 列表每行一个工点：序号、工点、照片数、带定位张数、坐标系、状态、备注。默认勾上「待处理」的；**带定位不到一半的**（状态「定位不足」）和**在子目录里的**（如 `无正射影像\` 下面的）默认不勾。
   - **排序**：点列头「照片数」按照片数排（点一下多→少 ▼，再点少→多 ▲，第三下回到扫描顺序）；点「序号」回到扫描顺序。排序方式记住，下次扫描沿用；序号不变（命令行 `--pick` 仍按序号）。
   - 第一次扫描要读每张照片开头的定位（网络盘上五千张约一分钟），扫描在后台进行，可以点「取消」；同一次打开软件里再扫描很快。
3. **坐标系**：每个工点按带定位照片的**平均经度**自动选最近的 3 度带（中央经线 = 3 × round(经度 / 3)，EPSG = 4534 + (中央经线 − 75) / 3，如兰州一带 CM 102°E = EPSG:4543）。经度离分带线（中央经线 ±1.5°）不到 0.1° 的在备注里标「靠近分带线」，这类工点自动选的带可能和以往成果不同，请核对。
   - 在列表的「坐标系」下拉框里可以**逐个改**；改过的按工点名记住，下次扫描沿用；选回「自动 …」就恢复自动。
   - 「坐标系全部统一为」选一个带再点「统一」，所有工点都改成它（也记住）；选「自动（按工点）」再点「统一」全部恢复自动。
4. 选项：「同时出 DOM、DSM」默认不勾（很慢）；分辨率默认 0.03 米（填「自动」= Metashape 给的原始分辨率）；关键点 40000、连接点 10000。对齐精度固定为「最高」。
   - 勾了 DOM/DSM 后，下面还有「**自动裁边（背景透明）**」（**默认勾**）、「**往里收**」（默认 **3 米**，可填 0～30）和「**点云密度门槛**」（默认 **50 %**，可填 10～90）：见下面 4.1。
5. 点「开始」：勾上的工点**按列表里的顺序**一个接一个跑（不并行；比如先按照片数少→多排，小工点先出结果）；本机有别的 Metashape 在跑就先等。「取消」停在当前工点、剩下的不开始；关窗口会先问。
   - 勾了 DOM/DSM 时，「**处理完自动整理交付目录**」默认勾：全部跑完（没取消）后，把这次勾选里完成的工点整理到交付目录，见下面 4.2。
   - 完成 / 部分对齐的工点下次扫描算「已有结果」、跳过；失败或已取消的显示「待处理（上次失败|已取消）」，重跑前旧结果目录改名为 `<工点名>_上次失败_<时间>` / `_上次已取消_<时间>` **保留**。
   - **对齐率低于 80% 判失败**、不出 XML；部分对齐时 XML 只写已对齐的照片，`.psx` 保留全部，未对齐清单写在报告里。

#### 4.1 自动裁边（背景透明）

以前出的 DOM/DSM 是整幅的：边上有一圈影像被拉长、高程乱跳的「拉花」，外框也比实际航测区大一圈。以前要拿 Global Mapper 手动裁。现在默认自动裁（v1.2 起按下面的三条判据；v1.1 只看 DSM 有没有值，而 DSM 是插值过的，范围会跑到影像外面，已经不用了）：

- **一块地方算「有效」要同时满足三条**（在 0.5 米见方的格子上判断）：
  1. **影像有内容**：没裁的 DOM 在这一格里不透明的像元 ≥ 90 %；
  2. **真有点云**：用密集点云另建一张**不插值**的辅助 DSM（0.1 米，只用来判断，不输出、用完就删，正式 DSM 不动），这一格里有真实的点；
  3. **点云够密**：以 1 米见方为一块，块里有真实点的 0.1 米小格占比 ≥「**点云密度门槛**」（默认 50 %）。拉花的地方点又稀又乱，会在这条被去掉。
- **再整理成一条线**：把细缝补上（先往外扩 1 米再往里收 1 米）→ 取面积最大的一整片 → 填掉内部小于 100 m² 的洞 → 沿边界**往里收**设定的米数（默认 3 米）→ 简化成多边形（相邻点间距 ≥ 1 米）。所以范围线一定在「DOM 有影像」的地方里面，不会伸到影像外。**跟正摄还是斜飞没关系**，一律这么算。
- **怎么裁**：DOM 和 DSM 用**同一条范围线、同一个像元网格**裁：线外 DOM 的 alpha = 0（透明）、DSM = NoData（−9999）；外框 = 范围线外接矩形外扩 5 个像元；两者的左上角、像元大小、行列数完全一致（后面算方量要用，软件会自动核对）。分辨率、数据类型、坐标系、文件名都同以前。裁边要多花几分钟：建辅助 DSM（百张左右的工点 2～3 分钟）和按线重新导出（1～2 分钟）。
- **生成范围（v1.3 起）**：勾了自动裁边时，DOM/DSM 的平面范围 = Metashape 对齐后自动给的区域框 **∪** 连接点（稀疏点云）东、北各自 0.1 %～99.9 % 分位数的范围，再限制在已对齐相机平面范围 ± 1000 米以内（高程方向用自动区域框的）。以前只用自动区域框，它有时比连接点小一圈（个别工点 DOM 一侧会被截成直边）；现在先生成大一些，多出来的边角由上面的三条判据裁掉，代价是建模时间长一些。不勾自动裁边时同 v1.2（自动区域框，外伸超过相机范围 200 米的边收到 ± 200 米）。报告里写自动区域框、连接点范围、最后用的范围和有没有被 ± 1000 米收过。
- **两个参数怎么调**（改了都会记住：config.json 的 `survey_inset`、`survey_density`，勾选框是 `survey_clip`）：
  - 「**往里收**」：沿边界往里缩多少米。填 0 = 不额外收；填大一点（如 5～10）= 更狠地切掉边缘，代价是面积变小。
  - 「**点云密度门槛**」：调低（如 30）= 点云稀一点的地方也留着，范围大一些；调高（如 70）= 裁得更狠。两个测试工点实测 10～90 都是一整块、没有碎斑，面积只差几个百分点。
- **范围线文件**：每个工点会多两个文件 `<工点名>_范围线.kml`（WGS84 经纬度，给 Google Earth、奥维等看）和 `<工点名>_范围线.shp`（+.shx/.dbf/.prj，坐标系同 DOM，给 ArcGIS / QGIS / Global Mapper 用），另有一个 `<工点名>_裁边分析.json.gz`（三条判据的分析结果，只改两个参数重新裁时直接用它，不用再进 Metashape 分析）。
- **自己手动裁（按范围线重新裁剪）**：自动的线不满意（比如某块不想要、某块想加回来），不用重跑：
  1. 用任何 GIS 软件改范围线：可以有**多个多边形**（都保留），多边形里画**内环＝把那一块挖掉**。KML 按 WGS84 经纬度读；SHP 按它的 `.prj` 自动换算（WGS84 经纬度、别的 3 度带、带不带带号都行；没有 `.prj` 当作和 DOM 同坐标系）。
  2. 在「影像处理」页签点「**按范围线重新裁剪…**」：勾工点（输出目录里已完成、出过 DOM/DSM 的），范围线来源三选一：
     - 用工点目录里的 `<工点名>_范围线.kml / .shp`（你改过后按原名放回去的；两个都在用较新的那个）；
     - 用你选的任意一个 KML 或 SHP 文件；
     - 不换线，只改「往里收」「点云密度门槛」重新自动算。
  3. 只重新导出 DOM/DSM，**不碰空三和建模**，一个工点一两分钟（实测约 1.3 分钟；重新自动算且没有分析缓存时 5 分钟左右）。先导到临时文件、检查通过才替换；旧的范围线改名保留成 `<工点名>_范围线_上次_<时间>.kml/.shp`，新用的那条按原名写回；`处理报告.txt` 的裁边段改写，写明来源（自动 / 工点目录里改过的线 / 你选的文件路径）和时间。外框会跟着线变（行列数、左上角都可能变，像元网格不变），报告里写「外框已随范围线改变：旧 W×H → 新 W×H 像元」，叠新旧图时别以为错位了。你自己的线**原样裁**，不再往里收、不按点云判据删减。
  4. 命令行同样能做：`survey-clip <工点输出目录>... [--line 范围线.kml|.shp] [--clip-inset 3] [--clip-density 50]`（不给 `--line`：工点目录里的线比报告新就用它，否则按参数重新自动算）。
  - 重跑整个工点时，工点目录里的范围线文件比 `处理报告.txt` 新，也照样按你的线裁（同 v1.1）；或者 `survey-batch --clip 我的范围线.shp`。
  - 也可以照旧拿裁好的 DOM/DSM 到 Global Mapper 等软件里自己再裁：背景是透明的、DOM 和 DSM 网格一致，不影响。
- 不想裁：界面取消勾选「自动裁边」，或命令行 `--clip none` —— 输出和 v1.0 一样（整幅导出，逐字节相同，实测过）。
- 报告里会写：范围线来源、点云密度门槛、往里收多少米、**三条各淘汰了多少面积**、补缝/连片/填洞后的面积、范围线面积、**裁剪前后外框**（米、像元数）、范围线文件路径。

**每个工点的输出** `<输出目录>\<工点名>\`：

| 文件 | 说明 |
|---|---|
| `<工点名>.psx` + `.files` | Metashape 工程（全部照片） |
| `<工点名>_BlocksExchange.xml` | 给 CC 导入：坐标系写 `<SRS>`：`CGCS2000 / 3-degree Gauss-Kruger CM 102E` / `EPSG:4543`（按该工点实际用的带），区块挂这个坐标系；照片路径是原片的绝对路径 |
| `<工点名>DOM.tif` + `.tfw` | （勾了才有）正射影像：RGBA 8 位（透明区 alpha=0）、Deflate 压缩、默认 0.03 米、坐标系同上；超过 4 GB 自动 BigTIFF。勾了自动裁边时线外透明、外框缩到范围线 |
| `<工点名>DSM.tif` + `.tfw` | （勾了才有）数字表面模型：32 位浮点、NoData −9999、与 DOM 同外框同分辨率同像元网格（线外也是 NoData） |
| `<工点名>_范围线.kml` | （勾了自动裁边才有）裁剪范围线，WGS84 经纬度；改了用「按范围线重新裁剪…」只重新导出 |

#### 4.2 整理交付目录（只放 DOM/DSM）

交付给别人时不需要工程、XML、范围线、日志这些：交付目录里**每个工点一个文件夹，只放 4 个文件** `<工点名>DOM.tif`、`<工点名>DOM.tfw`、`<工点名>DSM.tif`、`<工点名>DSM.tfw`（文件名不变），根目录一份 `交付清单.csv`。

- 交付目录默认是输出目录**同级**的 `<输出目录名>_交付`（如输出 `G:\新建文件夹` → 交付 `G:\新建文件夹_交付`）；「交付目录」框里填了就用填的（记住）。不能放在输出目录或照片目录里面。
- 两种用法：①勾「处理完自动整理交付目录」，跑完自动做（只整理这次勾选的工点）；②随时点「**整理交付目录…**」，把输出目录里**所有**完成 / 部分对齐、DOM/DSM 齐全的工点整理过去（先弹框确认工点数、大小和位置）。只出了 XML 的工点不放，会列出来。
- **是复制**：输出目录里的处理结果原样不动（以后还能「按范围线重新裁剪」）。每个文件先写成临时文件，读回来核对 SHA-256 和原文件一致才换上，修改时间保持原样；对不上就不换、报失败。
- 再整理一次时，大小和修改时间都没变的文件**不重复复制**（显示「已是最新」）；重新裁剪过的工点会重新复制。点「按范围线重新裁剪…」时，如果交付目录里已经有清单，裁完会自动把这几个工点更新过去。交付目录里你自己放的别的文件不动、不删。
- `交付清单.csv`（UTF-8 带 BOM）每个文件一行：工点、文件名、大小（字节）、SHA-256、坐标系（从处理报告读，如 `EPSG:4543 CGCS2000 / 3-degree Gauss-Kruger CM 102E（东坐标不带带号）`）、分辨率（米，从 .tfw 读）、行×列（tif）、DOM 与 DSM 行列是否一致、处理状态（完成 / 部分对齐）、来源（`Metashape` 或 `CC:<Production 目录名>`）、来源标识（来源的唯一 ID，CC 的是 Production 目录的完整路径）、判据（用的哪组裁边判据；4.2 的 Metashape 成果写「①DOM有影像+②③真实点云」或「未用点云判据（原因）」）。日志在输出目录的 `整理交付日志_<时间>.txt`（或这次影像处理的日志里）。
- 命令行：`survey-deliver <输出目录> [--to 交付目录] [--site 工点名,...]`；或 `survey-batch ... --dom-dsm --deliver [--deliver-to 交付目录]` 跑完自动整理。

#### 4.3 整理 CC 成果（v1.6）

在 ContextCapture / iTwin Capture Modeler 里导入 XML、出了 DOM/DSM 或 3SM 之后，CC 的输出目录只叫 `Production_1`、`Production_2`，不带工点名。点「**整理 CC 成果…**」，软件自己认出每个成果是哪个工点，再整理进 4.2 的交付目录：

1. 先在「输出目录」里选影像处理的输出目录（候选工点就从这里找：完成 / 部分对齐、有 `<工点名>_BlocksExchange.xml` 的）。
2. 在弹框里加 CC 目录（CC 工程目录、它下面的 `Productions`，或某个 `Production_*` 目录都行，可以加好几个工程），点「扫描」，列出每个成果：类型、外框、认到的工点、得分、状态。
3. **怎么认**：成果外框（DOM/DSM 用 `.tfw` + 行列数，3SM 读文件里根节点的外框）和每个工点「已对齐相机的平面范围」比，**坐标系（EPSG）一样的才比**；得分 = 重叠面积 ÷ 成果外框面积。最高分 ≥ 0.5、且第二名不到最高分的一半，才自动认定；否则（比如同一地点不同日期的两个工点）不猜，在「工点」一栏的下拉里自己选（不想整理就选「（不整理）」）。同一个工点认到两个同类成果（如两个正射）也要自己选。只有分块、没有 `*_merge.tif` 的 Production 列为「未合并，跳过」；读不出坐标系的列为「坐标系不明」；**DOM 和 DSM 的 GeoTIFF 里的 EPSG 不一致（冲突）直接不整理**（`ContextScene.json` 只在 GeoTIFF 读不出时补上，不会盖掉 GeoTIFF 里的值）。
4. 点「开始整理」。每个工点文件夹里放 `<工点名>DOM.tif/.tfw/.tif.ovr`、`<工点名>DSM.tif/.tfw/.tif.ovr`（`.ovr` 是金字塔），有 3SM 的再加 `<工点名>.3sm`（逐字节复制、只改名）。

- **裁边**（默认勾，可以不勾）：同 4.1 的做法——0.5 米网格上 ①CC 的 DOM 有影像（**RGB 三通道不全为 0** 的像元 ≥ 90%；图带透明通道时透明的地方也不算数），②③ 工点的 `.psx` 里有密集点云时用它算「真实点云够密」（要 Metashape）；工点工程里没有密集点云（只出过 XML）或没有 `.psx` 时，用 ④CC 的 DSM 有值代替，报告和清单里都写明「未用点云判据」。然后补缝、取最大连片、填小洞、往里收（默认 3 米）。**不重采样**：留在 CC 原来的像元网格和分辨率上，DOM 输出带透明通道（线外透明），DSM 线外是 NoData −9999，DOM、DSM 外框和像元网格完全一致；金字塔重新生成（CC 原来的 `.ovr` 跟裁过的图对不上，不会复制）。范围线另存为 `<工点名>_CC范围线.kml/.shp`，放在**输出目录**的工点目录里，不进交付目录。
- **不裁**时：CC 的 tif、tfw、`.tif.ovr` 改名原样复制（CC 没给金字塔的话软件给它建一个 `.ovr`，tif 本身不动）。**tif、tfw、`.ovr` 当同一套换**：换主图时金字塔必须跟着换 —— 源有 `.ovr` 就一起复制，源没有就把交付目录里上一版的旧 `.ovr` 删掉重建（不然 QGIS 之类的软件缩览时读到的是旧图的值）。软件核金字塔的办法：读每一级的真实尺寸和倍数对不对得上，再抽查读值（金字塔某个像元的值要在主图对应那一块的取值范围内）；固定抽查点全落在 NoData 里（有效区是窄斜带之类）时，软件会在这一级的**有效像元**里另找样点，「没抽到可比的读值」不算文件损坏。抽查只在**新的一套**文件上做，用来验新文件对不对，不能拿来证明旧 `.ovr` 还能继续用 —— 主图一换（哪怕只有局部几个像元变了），交付目录里的旧 `.ovr` 一律作废重建（源有配套 `.ovr` 才跟着复制）。
- **坐标系**：DOM 和 DSM 的 GeoTIFF 里写的 EPSG 必须一致，不一致就**直接不整理**（报「坐标系冲突」）；`ContextScene.json` 里的 EPSG 只在 GeoTIFF 读不出来的时候用来补，不会盖掉 GeoTIFF 里写的值。两个都读不出来才报「坐标系不明」。补出来的 EPSG 会写进**裁边后**的成果（只是补坐标系的标签，像元网格和像素值一个不动、不重投影）。
- 交付目录里这个工点已经有同名文件、但来源不一样（比如 4.2 放进去的 Metashape 的 DOM），会先弹框问要不要换成 CC 的；选「否」就不覆盖、这个成果不整理。反过来，「整理交付目录…」也不会把交付目录里 CC 的成果换回 Metashape 的。
- **清单里的哈希**：`交付清单.csv` 里每一行的 SHA-256 是**文件最终落定后**重算的（含重建过的金字塔），和交付目录里的实际文件逐个重算一致。
- **来源身份**：`交付清单.csv` 里有一列「来源标识」= 这个成果的 **Production 目录的完整路径**（同一台电脑上唯一）。只写 `CC:Production_2` 时，两个不同工程里都叫 `Production_2` 的成果分不出来，会互相覆盖；现在按完整路径分。交付目录里已有的同名文件，来源标识**对不上就不覆盖**（哪怕「来源」那一列写着 `CC:Production_2`），要换得加 `--replace`。老清单（v1.5 写的、没有「来源标识」列）里的 CC 来源一律当「来源不明」，也一律不覆盖。
- `交付清单.csv` 加了一列「来源」：`Metashape` 或 `CC:<Production 目录名>`；还有一列「**判据**」，写明这个文件用了哪一组裁边判据（`①DOM有影像+④DSM有值`、`①DOM有影像+②③真实点云`、或 `3SM（逐字节复制，不裁）`），没用点云判据时把原因写在括号里（例：`①DOM有影像+④DSM有值（未用点云判据（工点工程 XXX.psx 里没有密集点云））`）。工点的 `处理报告.txt` 末尾追加一段「CC 成果整理」：来源目录和来源标识、认定方式（自动 + 得分 / 用户指定）、**用了哪组判据**、裁边的各项数字、交付了哪些文件。日志在输出目录的 `整理CC成果日志_<时间>.txt`。
- CC 的目录只读，一个字节都不改。
- 已知情况：CC 在没纹理的地方会填纯灰色（128,128,128），工点没有密集点云时这些灰块 RGB 不是黑的、会被当成「有影像」留下；工点有密集点云时由点云判据决定。
- 命令行：`survey-cc-deliver <CC工程或Productions目录>... --out <输出目录> [--to 交付目录] [--map Production_2=工点名,...] [--no-clip] [--clip-inset 3] [--clip-density 50] [--replace] [--plan]`。认不准的成果要用 `--map` 指定，不然跳过并报出来；`--plan` 只列认定结果、不写文件；交付目录里有来源不同的同名文件时要加 `--replace` 才换。

**在 ContextCapture 里导入**：新建工程 → 导入区块（Import blocks）→ 选 `<工点名>_BlocksExchange.xml`。应看到：照片全部找到（路径里有 `#`、`、`、`+` 的也要找到）、区块坐标系是 CGCS2000 / 3-degree Gauss-Kruger CM 102E（或该工点的带）、照片都已有位置姿态（已空三），直接可以建重建任务，不用再空三。

**大概要跑多久**（本机 i7-12700H + RTX 3050 Laptop 4 GB，照片在网络盘上）：见 `处理报告.txt` 的「各步耗时」；百张左右的工点只出 XML 约 3～4 分钟，加 DOM/DSM（超高）要长得多，三百张的工点可能要几个小时。

命令行：

```powershell
uav_photo_tool.exe survey-batch <照片上级目录> --out <输出目录> `
    [--epsg auto|4543] [--dom-dsm] [--resolution 0.03|auto] [--clip auto|none|范围线.kml|.shp] [--clip-inset 3] `
    [--clip-density 50] [--include "*弃渣场*"] [--pick 1,3,5-9] [--skip 名字1,名字2] [--plan] [--keypoints 40000] `
    [--tiepoints 10000] [--sort scan|photos-desc|photos-asc] [--deliver [--deliver-to 交付目录]] `
    [--metashape 路径] [--log 日志文件]
uav_photo_tool.exe survey-clip <工点输出目录> [<工点输出目录> ...] [--line 范围线.kml|.shp] [--clip-inset 3] `
    [--clip-density 50] [--metashape 路径] [--log 日志文件]
uav_photo_tool.exe survey-deliver <输出目录> [--to 交付目录] [--site 工点名1,工点名2] [--log 日志文件]
uav_photo_tool.exe survey-cc-deliver <CC工程或Productions目录> [...] --out <输出目录> [--to 交付目录] `
    [--map Production_2=工点名,...] [--no-clip] [--clip-inset 3] [--clip-density 50] [--replace] [--plan] `
    [--metashape 路径] [--log 日志文件]
```

- `--epsg auto`（默认）每个工点自动选带；`--epsg 4543` 整批统一用这个带。命令行不读界面里记住的逐个修改。
- `--clip auto`（默认）按上面 4.1 的三条判据自动算范围线；`none` 不裁（同 v1.0）；也可以给一个 `.kml` / `.shp` 文件按它裁。`--clip-inset` 是往里收多少米（0～30，默认 3），`--clip-density` 是点云密度门槛（10～90，默认 50）。不给 `--dom-dsm` 时这几个参数不起作用。
- `survey-clip`（按范围线重新裁剪）：退出码 0 成功 / 1 有失败 / 2 参数错误；`--line` 给的线原样裁，不能再和 `--clip-inset` / `--clip-density` 一起用。
- `--sort`：处理顺序，`scan` 扫描顺序（默认）/ `photos-desc` 照片数从多到少 / `photos-asc` 从少到多（照片数一样的按序号）。
- `survey-deliver`（整理交付目录，见 4.2）：退出码 0 成功 / 1 有工点没整理成 / 2 参数错误（如交付目录在输出目录里、`--site` 的工点不是完成且有 DOM/DSM 的）/ 3 已取消。`survey-batch --deliver` 要配 `--dom-dsm`；交付有失败时退出码算 1。
- `survey-cc-deliver`（整理 CC 成果，见 4.3）：退出码 0 成功 / 1 有成果没整理成（含没认出、未合并、坐标系不明、交付目录里有来源不同的文件没加 `--replace`）/ 2 参数错误（如 `--map` 写错、指定的工点不是候选或坐标系不同）/ 3 已取消；`--plan` 时全部能认出返回 0，否则 1。
- 不给 `--include` / `--pick` 时只处理界面里默认会勾的工点（待处理、且不在子目录里）；给了就从全部工点里按名字通配符 / 序号选（两个一起用取交集）。先加 `--plan` 看一遍序号和每个工点的坐标系。

## 下载

到 [Releases](https://github.com/aduhappy/uav-photo-tool/releases) 下载最新的版本，有**两种**给法，任选一种：

| 附件 | 怎么用 |
|:--|:--|
| `无人机照片工具_v<版本>_安装包.exe` | 双击安装。**默认装到 `%LOCALAPPDATA%\Programs\无人机照片工具\`**（当前用户目录，**不需要管理员权限**），向导里可以改目录。装完在开始菜单有快捷方式，桌面也有（默认勾，可以去掉）。 |
| `无人机照片工具_v<版本>_免安装.zip` | 解压到任意目录，双击里面的 `无人机照片工具.exe` 就能用。适合放在 U 盘里、或者不想装东西的场合。 |

两种给法里的程序**是同一份**，功能一样。

- **怎么卸**：安装包在「设置 → 应用」里找「无人机照片工具」卸载，或者直接跑安装目录里的 `unins000.exe`。也可以在「开始菜单 → 无人机照片工具 → 卸载」。
  卸载**只删程序文件**，不会删你的设置和配置（`%APPDATA%\无人机照片工具\config.json`）和任何用户数据——重装后设置还在。
- **升级**：装新版本时，安装程序会先清理安装目录里本工具旧版留下的程序文件，再安装新版本；只处理安装目录，不会碰配置和用户数据。请不要把个人文件放进安装目录。
- 免安装 zip 不用卸载：把解压出来的文件夹删了就行。
- 两个附件都**自带 GDAL / PROJ / numpy / shapely / pyproj**（约 180 MB），不用另外装 Python 或任何库。程序用的 GDAL 数据是它自己包里那份，**不会**读你电脑上装过的 GDAL / PROJ / QGIS / conda 的环境变量。
- 想确认程序没问题：在命令行里跑 `无人机照片工具.exe selftest`，会检查 GDAL/PROJ/numpy/shapely/sqlite3 能不能用（包括 GDAL 和 pyproj 各自的 `proj.db` 文件及坐标换算），退出码 0 就是全好（界面里也有：菜单「帮助 → 自检」）。

软件启动时会在后台查一次有没有新版本，有的话会弹窗提示并给出下载链接，不会自动下载或替换。不想要这个提示，可以在菜单「帮助 → 启动时自动检查更新」里关掉。

## 系统要求

- Windows 10 / 11，64 位。
- 「剔除定位」不需要安装任何东西。
- 「空三」「控制点」「批量迁移」「影像处理」需要 Metashape **Pro** 版（标准版不支持脚本，用不了）。目前只在 Metashape Pro 1.7.2 上实测过，2.x 和 PhotoScan 1.4 没有测过，欢迎反馈。
- 已测试的相机：DJI M3E（Mavic 3 Enterprise）；「影像处理」用 DJI Mavic 3 系列（Hasselblad L2D-20c）实景照片测过。其他大疆机型的照片结构相近，应该也能用；遇到问题请提 Issue。
- 从 v1.5 起是**文件夹版**（不是一个 exe）：启动直接读程序目录里的文件，比以前单文件 exe 每次启动要解压一遍要快。

## 从源码运行和打包

- 源码只有一个文件 `src/uav_photo_tool.py`。需要 Python 3.8 或更高版本（带 tkinter）。图形界面要用界面库 CustomTkinter（版本钉在 `requirements-gui.txt`）；处理用的地理库 numpy / rasterio（含 GDAL）/ shapely / pyproj 版本钉在 `requirements.txt`：

  ```powershell
  python -m pip install -r requirements-gui.txt   # 界面
  python -m pip install -r requirements.txt        # 地理库（GDAL 裁边等新功能要用）
  python src/uav_photo_tool.py            # 启动界面
  python src/uav_photo_tool.py --help     # 命令行
  python src/uav_photo_tool.py selftest   # 自检：GDAL/PROJ/numpy/shapely/sqlite3 能不能用
  ```

  界面支持浅色（默认）/ 深色 / 跟随系统，在菜单「外观」里切换，会记住。

- 打包成**文件夹版 + 安装包 + 免安装 zip**（v1.5 起；以前是单文件 exe，脚本 `scripts/build_exe.ps1` 已标「已取代」）：
  用一个**干净的 Python 3.11 环境**（不要用 conda 的 env——conda 装的 numpy 依赖 MKL，DLL 在 `Library\bin` 里带不走），先装好版本钉死的依赖，再跑打包脚本。脚本开头会核对已装版本和 `requirements*.txt` 一致，不一致就停：

  ```powershell
  python -m venv .venv
  .venv\Scripts\python -m pip install -r requirements.txt -r requirements-gui.txt
  .venv\Scripts\python -m pip install pyinstaller==6.22.3
  pwsh -File scripts/build_installer.ps1 -Python .venv\Scripts\python.exe -Build <中间文件目录>
  ```

  脚本做三件事：① PyInstaller `--onedir --windowed` 打文件夹版；② 调 Inno Setup 6 编译安装包 `发布\无人机照片工具_v<版本>_安装包.exe`（安装脚本在 `installer\uav_photo_tool.iss`，中文向导用 `installer\ChineseSimplified.isl`）；③ 打免安装 zip `发布\无人机照片工具_v<版本>_免安装.zip`（zip 里中文文件名带 UTF-8 标志，非中文系统的解压工具不会乱码）。版本号只从源码的 `APP_VERSION` 读。

  还需要装 Inno Setup 6（默认在 `C:\Program Files (x86)\Inno Setup 6\`）。

- 测试脚本（需要 Pillow）：

  ```powershell
  python scripts/test_strip_gps.py <原片目录> <去定位输出目录> [--pixels]
  python scripts/test_align.py <空三输出目录> [--expect-aligned N] [--metashape 路径]
  python scripts/test_gcp.py <控制点输出目录> [--expect-aligned N] [--max-rms 0.02] [--metashape 路径]
  python scripts/test_gui.py --mode invoke --out <结果目录> --data <测试照片副本根> --metashape 路径 --ref <参考期.psx> --appdata <临时目录>   # 界面：进程内点每个按钮
  ```
